# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Milheirador is a client-only React 19 + Vite app, prerendered to static HTML at build time, styled with Tailwind CSS v4 and shadcn/ui, that ranks Brazilian credit cards by the miles they earn (the Índice Milheirador, plus miles per R$ and extra miles per R$ of annuity) across all points programs (Livelo, Esfera, airline programs, banks' own programs). The UI text is in Portuguese (pt-BR). There is no backend, router library, or state library, and no test framework is set up.

## Commands

```bash
npm install
npm run dev       # Vite dev server with HMR
npm run build     # client build + SSR build + scripts/prerender.js, to dist/ (fails while src/site.js is empty)
npm run preview   # serve the built dist/
npm run lint      # ESLint (flat config, eslint.config.js)
npx shadcn@latest add <component>   # add a shadcn/ui component to src/components/ui
```

## UI stack

- Tailwind v4 is configured through `@tailwindcss/vite` and has no tailwind config file. The theme tokens (CSS variables) live in `src/index.css`, in `:root` (light) and `.dark`. They follow the brand palette: Verde Milheirador `#0F5132` as primary, Amarelo Milho `#FFC107` as `highlight`, Creme background, Verde Carvão dark background. There are also `sage`, `success`, `warning` and `info` tokens (Tailwind classes such as `bg-highlight` and `text-success`).
- Contrast rules: yellow is only a fill, always with `text-highlight-foreground` (dark text), and never text or an icon on light surfaces. In dark mode `--primary` is a lighter green (`#7CCB98`) because `#0F5132` on `#1B211D` is only 1.75:1.
- Dark mode uses the `.dark` class on `<html>`. An inline script in `index.html` applies the saved or system theme before paint, and `ThemeToggle` switches it and stores the choice in `localStorage.theme`.
- Fonts: Geist (body) and Nunito (`font-heading`, which echoes the rounded wordmark). The logo assets are `public/logo.png` (transparent mark), `favicon.png` and `apple-touch-icon.png`, all generated from `public/Logo Milheirador.png`.
- `components.json` sets up shadcn/ui with the `radix-nova` style, JSX (`tsx: false`) and Lucide icons. `src/components/ui/*` is generated by the CLI, so prefer re-adding a component over hand-editing it. The `cn` helper re-exports from the `cn` package (shadcn's own).
- The `@/` alias points to `src/` (`vite.config.js` + `jsconfig.json`).
- Touch targets: radix-nova's sizes (28–36px) suit a mouse. At the end of `index.css`, a `@media (pointer: coarse), (max-width: 639px)` block raises buttons (except `variant="link"`), inputs, input groups, select triggers and select items to 44px by `data-slot`, so the generated components stay untouched. Add `touch-target` to standalone text links and link buttons. Beware `flex-1` on buttons in a `flex-col` container: the 0 basis overrides their height (it squashed Calcular/Ver ranking on phones), so use `sm:flex-1`. Below `md` the header links are in a menu button (`menuOpen` in `App`).
- The Radix `Select` can't use `""` as an item value; the ranking filters use the sentinel `"all"`.

## Architecture

- `src/data/cards.js` exports `creditCards`, a hand-maintained static array that serves as the whole dataset. Each entry has `id, brand, issuer, type, program, accumulationFactor, accumulationFactorAbroad, conversionRatio, currency, annuity`. Values are lowercase; display labels come from `src/utils/format.js`. `currency` is `"dolar"` (points per US$) or `"real"` (points per R$). `program` is where the points go (`livelo`, `esfera`, `latam pass`, `azul fidelidade`, `smiles`, `aadvantage`, `tap miles&go`, or `proprio` for the bank's own program). Cards whose network is unknown or varies ("Visa / Mastercard") have `brand: null`. The dataset was regenerated from `milheirador_catalogo_consolidado_2026-11-08.csv` (bank programs mapped to `proprio`, `accumulationFactorAbroad` = `accumulationFactor` since the CSV has no international column).
- `src/utils/rankMyCard.js` holds the scoring logic (see "Ranking indicators" below). `evaluateCard` adds `milesPerReal`, `annualMiles` and `milheiradorIndex` for a given `{ monthlySpend, dollarRate }`; `rankCards` also adds `additionalMilesPerFeeReal` against `freeReferenceCard` and sorts by a key of `RANKING_CRITERIA` (default `"index"`, lowest first); `sortCards` re-sorts already ranked cards.
- Every navigation is a **full page load** through plain `<a href>` links (no router library), because AdSense vignettes only show on link navigation. The paths are `/` (home), `/resultado` (home with the result), `/ranking`, `/onde-comprar` and the text pages in `src/pages/` (`/como-calculamos`, `/programas`, `/perguntas-frequentes`, `/sobre`, `/privacidade`, `/contato`). `src/routes.js` lists every path with its `<head>` title and description (`noindex` for `/resultado`); `App` maps the text paths to their components. The form travels in the query string (`gasto`, `dolar`, `banco`, `cartao` and optionally `anuidade` (the annuity the user pays for that card, 0 with an exemption), or `manual=1` plus the manual card fields); `cardFromProfile` applies that annuity, and `App`'s `rankWith` puts the user's card in place of its dataset entry; `src/utils/profile.js` holds the paths, `profileHref`, `profileFromSearch`, `settingsFromProfile` and `cardFromProfile` (the profile's card, or null while the form is invalid).
  - **Home / result:** a centered `UserProfileForm` with **Calcular** and **Ver ranking** buttons. While the form is valid, Calcular is a link to `/resultado?…`; otherwise it is a submit button that only shows the errors. On `/resultado`, `TopRanking` shows the top 3 plus the user's card (with a "…" row when it is below 3rd).
  - **Ranking:** `CardRankingList` (an "Ordenar por" select over `RANKING_CRITERIA`, with the annuity criterion disabled when there is no free reference; filters for bank, network, program and max annuity, 10 per page), ranked with the profile from the URL and highlighting its card when it is valid.
  - **Onde comprar** (`/onde-comprar`, `src/pages/WhereToBuy.jsx`): `WorthCalculator` compares 2+ stores for the same product. The math is in `src/utils/purchase.js`: `evaluateStore` (final price = product + shipping − discount; card points on `cardEligibleAmount` via `pointsPerReal` from `rankMyCard.js`, times the card's `conversionRatio`; partner campaign points on `eligiblePartnerAmount`, times the store's `partnerConversionFactor`; estimated net cost = final price − miles ÷ 1.000 × the milheiro value, default R$ 35, suggested R$ 20–50) and `compareStores` (the reference is the lowest price, then more miles; per store the additional milheiro cost, net switch benefit, maximum extra payment and the exact break-even final price `maxWorthPrice`; `best` by net cost, then price, then miles, with ties kept). A null eligible amount means the final price, so it moves with the price in `maxWorthPrice`. The annuity is left out (the user already has the card). `partnerPointsMode` is always `"additional"` for now. A card is required before the comparison shows. The card and dollar rate come from the shared `profile` (its edits rewrite the URL to `/onde-comprar?…`); the stores and milheiro value are local state, starting from the spec's example (R$ 14,90 vs R$ 17,88 with 2 pts/R$). The card selects are `CardPicker` and the R$ inputs `MoneyField`, both shared with `UserProfileForm`. Once a card is picked, the header/footer links to `/ranking` and `/onde-comprar` carry the profile.
- **Prerendering:** `App` takes `path` and `search` as props (`main.jsx` passes `window.location`). `npm run build` also builds `src/entry-server.jsx` with `vite build --ssr`, and `scripts/prerender.js` renders every route with an empty query into `dist/<path>.html` (`/` → `index.html`), with its own title, description, canonical URL, plus `sitemap.xml` and `robots.txt`. So crawlers see the text without JS (this was the AdSense "low-value content" rejection). Cloudflare Pages serves `ranking.html` at `/ranking`. The client uses `createRoot` (not hydration) and simply renders over the static HTML, so query-string state never causes hydration mismatches. Code that runs during render must not touch `window`/`document` unguarded.
- `src/site.js` holds `SITE_URL` (canonical URLs, sitemap) and `CONTACT_EMAIL` (contact and privacy pages); the prerender script fails while either is empty.
- Text pages use `Article` (title, intro, and `.article-body` styles in `index.css` for plain `h2`/`p`/`ul`/`a`/`code`). The home renders `HomeGuide` (how it works, formula, program counts) below the form. Numbers in the text come from the data and `rankMyCard.js` (counts, the worked example), not hard-coded.
- **Dollar rate:** `src/utils/dollarRate.js` fetches today's PTAX selling rate from the Banco Central's Olinda API (CORS allows the site; weekends/holidays are covered by asking for the last 10 days and taking the latest), cached in `localStorage.ptax` for 3 hours; on failure it returns the stale cache or null. App starts from the cached rate (none during prerendering) and fetches after mount. `profile.dollarRateAuto` is true until the user types a rate or the URL has `dolar`; while it is, `withDollarRate` replaces the rate with the PTAX, and `profileHref` leaves `dolar` out of the URL. `DollarRateField` (shared by the home form and `WorthCalculator`) shows the PTAX date and a button to go back to it. The privacy page mentions the request to the Banco Central.
- App reads `profile` from the URL once (spend and dollar-rate strings, `manual`, `issuer`, `cardId`, `manualCard` fields). Every change goes through `handleProfileChange`, which hides the result and rewrites the URL to `/?…` with `history.replaceState`. The ranking is recomputed on every render; the dataset is small.
- `UserProfileForm` is controlled by `profile` and only keeps a `submitted` flag for showing errors. In manual mode it renders `CardInputForm`, which only holds the fields (no `<form>` or submit button). The defaults, validation and conversion to a card (id `"my-card"`) live in `src/utils/manualCard.js`. A manual card is added to the ranking.
- `RankingTable` renders the table rows (`{ card, position }`, with position in the full ranking) for both `TopRanking` and `CardRankingList`, with a column per indicator (the sorting one in bold, and the only one on the right on small screens). `RankingLegend` explains the indicators below it and names the free reference card.
- Numeric inputs are text fields parsed with `parseNumber` (`format.js`). It reads pt-BR numbers: `"5.000,50"`, `"10.000"` (3-digit dot groups are thousands) and `"5,50"`, and also accepts `"5.50"`.
- Ads: the AdSense script and `google-adsense-account` meta tag are in `index.html`, and `public/ads.txt` is served at the domain root. `src/components/GoogleAds.jsx` renders one unit per `slot` key (`banner` or `content`, IDs in `AD_SLOTS`) and pushes it on mount. AdSense rejected the site for ads on screens without publisher content, so units only go next to editorial text: one `content` unit after `HomeGuide` on the home, and one mid-article on `/como-calculamos`, `/programas`, `/perguntas-frequentes` and in the text below the calculator on `/onde-comprar`. There are no units on `/ranking`, on `/sobre`, `/privacidade` or `/contato`, or next to the form, and the sticky bottom `banner` was removed (its slot ID is still in `AD_SLOTS`). Vignettes are AdSense Auto ads, turned on in the AdSense dashboard, not in code.
- International spend (`accumulationFactorAbroad`) is not part of the score yet.

## Ranking indicators

Implemented in `rankMyCard.js`, all on an annual basis with the annuity the user actually pays. In the data, `accumulationFactor` / `accumulationFactorAbroad` are points per unit of `currency`, `conversionRatio` converts points to miles, and `annuity` is the annual fee in BRL.

```
1. milhas por real = pontos por moeda × milhas por ponto ÷ cotação (÷ 1 for "real" cards)
2. milhas extras por R$ de anuidade = (milhas/ano − milhas/ano da referência) ÷ (anuidade − anuidade da referência)
3. Índice Milheirador = (gasto anual + anuidade) ÷ milhas/ano
```

- Indicator 1 leaves the annuity out; e.g. 2.5 ÷ 5.50 = 0,4545. Sorted highest first.
- Indicator 2's reference is the free card (annuity 0) with the most annual miles for the profile (`freeReferenceCard`; can be the user's exempted card). Free cards show "Não se aplica"; with no reference it is "Indisponível" and its sort option is disabled. Sorted highest first.
- Indicator 3 (the default sort, lowest first) is shown with 4 decimals and never as R$ or a mile price: the UI says it is not the market price of a mile. E.g. R$ 1.000/month, 1 pt/R$, 0.8 mi/pt, R$ 478,80 → 1,2999.
- Cards without a valid score (no miles) show "Indisponível" and sort last.
