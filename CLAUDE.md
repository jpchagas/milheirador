# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Milheirador is a client-only React 19 + Vite SPA, styled with Tailwind CSS v4 and shadcn/ui, that ranks Brazilian credit cards by the cost of each mile they earn across all points programs (Livelo, Esfera, airline programs, banks' own programs). The UI text is in Portuguese (pt-BR). There is no backend, router library, or state library, and no test framework is set up.

## Commands

```bash
npm install
npm run dev       # Vite dev server with HMR
npm run build     # production build to dist/
npm run preview   # serve the built dist/
npm run lint      # ESLint (flat config, eslint.config.js)
npx shadcn@latest add <component>   # add a shadcn/ui component to src/components/ui
```

## UI stack

- Tailwind v4 is configured through `@tailwindcss/vite` and has no tailwind config file. The theme tokens (CSS variables) live in `src/index.css`, in `:root` (light) and `.dark`. They follow the brand palette: Verde Milheirador `#0F5132` as primary, Amarelo Milho `#FFC107` as `highlight`, Creme background, Verde Carvão dark background. There are also `sage`, `success`, `warning` and `info` tokens (Tailwind classes such as `bg-highlight` and `text-success`).
- Contrast rules: yellow is only a fill, always with `text-highlight-foreground` (dark text), and never text or an icon on light surfaces. In dark mode `--primary` is a lighter green (`#7CCB98`) because `#0F5132` on `#1B211D` is only 1.75:1.
- Dark mode uses the `.dark` class on `<html>`. An inline script in `index.html` applies the saved or system theme before paint, and `ThemeToggle` switches it and stores the choice in `localStorage.theme`.
- Fonts: Geist (body) and Nunito (`font-heading`, which echoes the rounded wordmark). The logo assets are `public/logo.png` (transparent mark), `favicon.png` and `apple-touch-icon.png`, all generated from `public/Logo Milheirador.png`.
- `components.json` sets up shadcn/ui with the `radix-nova` style, JSX (`tsx: false`) and Lucide icons. `src/components/ui/*` is generated by the CLI, so prefer re-adding a component over hand-editing it. The `cn` helper re-exports from the `cn` package (shadcn's own).
- The `@/` alias points to `src/` (`vite.config.js` + `jsconfig.json`).
- The Radix `Select` can't use `""` as an item value; the ranking filters use the sentinel `"all"`.

## Architecture

- `src/data/cards.js` exports `creditCards`, a hand-maintained static array that serves as the whole dataset. Each entry has `id, brand, issuer, type, program, accumulationFactor, accumulationFactorAbroad, conversionRatio, currency, annuity`. Values are lowercase; display labels come from `src/utils/format.js`. `currency` is `"dolar"` (points per US$) or `"real"` (points per R$). `program` is where the points go (`livelo`, `esfera`, `latam pass`, `azul fidelidade`, `smiles`, `aadvantage`, `tap miles&go`, or `proprio` for the bank's own program). Two Santander cards still have `brand: null` (network unknown).
- `src/utils/rankMyCard.js` holds the scoring logic. `evaluateCard` adds `annualMiles` and `costPerMile` for a given `{ monthlySpend, dollarRate }`, and `rankCards` sorts cheapest miles first.
- Every navigation is a **full page load** through plain `<a href>` links (no router library), because AdSense vignettes only show on link navigation. The paths are `/` (home), `/resultado` (home with the result) and `/ranking`; Cloudflare Pages serves `index.html` for them because `public/` has no `404.html`. The form travels in the query string (`gasto`, `dolar`, `banco`, `cartao`, or `manual=1` plus the manual card fields); `src/utils/profile.js` holds the paths, `profileHref`, `profileFromSearch`, `settingsFromProfile` and `cardFromProfile` (the profile's card, or null while the form is invalid).
  - **Home / result:** a centered `UserProfileForm` with **Calcular** and **Ver ranking** buttons. While the form is valid, Calcular is a link to `/resultado?…`; otherwise it is a submit button that only shows the errors. On `/resultado`, `TopRanking` shows the top 3 plus the user's card (with a "…" row when it is below 3rd).
  - **Ranking:** `CardRankingList` (filters for bank, network, program and max annuity, 10 per page), ranked with the profile from the URL and highlighting its card when it is valid.
- App reads `profile` from the URL once (spend and dollar-rate strings, `manual`, `issuer`, `cardId`, `manualCard` fields). Every change goes through `handleProfileChange`, which hides the result and rewrites the URL to `/?…` with `history.replaceState`. The ranking is recomputed on every render; the dataset is small.
- `UserProfileForm` is controlled by `profile` and only keeps a `submitted` flag for showing errors. In manual mode it renders `CardInputForm`, which only holds the fields (no `<form>` or submit button). The defaults, validation and conversion to a card (id `"my-card"`) live in `src/utils/manualCard.js`. A manual card is added to the ranking.
- `RankingTable` renders the table rows (`{ card, position }`, with position in the full ranking) for both `TopRanking` and `CardRankingList`.
- Numeric inputs are text fields parsed with `parseNumber` (`format.js`). It reads pt-BR numbers: `"5.000,50"`, `"10.000"` (3-digit dot groups are thousands) and `"5,50"`, and also accepts `"5.50"`.
- Ads: the AdSense script and `google-adsense-account` meta tag are in `index.html`, and `public/ads.txt` is served at the domain root. `src/components/GoogleAds.jsx` renders one unit per `slot` key (`banner` or `content`, IDs in `AD_SLOTS`) and pushes it on mount. A responsive `content` unit sits at the bottom of each view, and a fixed-size `banner` unit sticks to the bottom of the screen (`.ad-banner`, hidden by `index.css` when AdSense returns no ad). Vignettes are AdSense Auto ads, turned on in the AdSense dashboard, not in code.
- International spend (`accumulationFactorAbroad`) is not part of the score yet.

## Intended scoring formula (from README)

Implemented in `rankMyCard.js`. The README describes miles earned per real (BRL) spent:

```
milhas por real = (pontos por dólar × milhas por ponto) ÷ cotação do dólar
```

For example, (1.5 × 1) ÷ 5.50 ≈ 0.2727 miles per BRL. For `currency: "real"` cards, skip the division. Cards are ranked by cost per mile = (annual spend + annuity) ÷ annual miles; the README example gives R$3.70. In the data, `accumulationFactor` / `accumulationFactorAbroad` are points per unit of `currency`, `conversionRatio` converts points to miles, and `annuity` is the annual fee in BRL.
